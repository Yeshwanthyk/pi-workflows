6 · Impl & verify slices

workflows built as small end-to-end slices
The same discipline applies inside workflows: a run is a stack of small impl slices, each followed by its verify slice before the next starts — so a failure is attributable to one exact slice. Phases are just phase() calls, so a workflow script already declares them; the UI renders each as a pipeline stage with its own progress and agents. Subagents get the same treatment: one agent per slice, impl:* and verify:* labels, model/provider chips so you can see which model did each slice.

what the code changes add

export interface AgentRecord { index: number; label: string; state: AgentState; + provider?: string; // "anthropic" — from Model.provider + modelName?: string; // "Claude Sonnet 4.5" — display name model?: string; // id, unchanged thinkingLevel?: WorkflowThinkingLevel; + thinkingPreview?: string; // latest reasoning excerpt (live) ... }
runner.ts — progress snapshot
const progressSnapshot = () => ({ preview: finalOutput(childSession.messages), + provider: sessionModel?.provider, + modelName: sessionModel?.name, + thinking: latestThinking(childSession.messages), usage: { ...usage }, transcript: transcriptFromMessages(...), ... });

Palette: pi dark theme — accent #8abeb7, border-accent #00d7ff, success #b5bd68, error #cc6666, thinking #b294bb. No new dependencies; everything renders with existing Theme.fg/bold + box-drawing characters.
